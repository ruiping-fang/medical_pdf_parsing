# 医学文档提取技能 - 设计文档

## 概述

**extract-medical-doc** 是一个专门用于从医学PDF文档中提取和结构化关键信息的 Claude Code 技能。它采用双层提取架构，在保留完整原始文本的同时智能识别医学实体。特别适用于临床指南、研究论文和药品说明书。

---

## 使用场景

### 1. **临床指南数字化**

**场景**: 医院需要将纸质或PDF格式的临床实践指南转换为结构化数据，以便集成到电子病历(EMR)系统中。

**使用方式**:

```bash
/extract-medical-doc 临床指南_2024.pdf
```

**交付价值**:

- 自动识别疾病名称和ICD编码
- 提取治疗方案和推荐等级(如 Grade A/B/C)
- 保留完整的诊断标准文本
- 分离药物名称和剂量，标记需要人工复核的部分

**真实案例**:
导入《成人高血压的药物治疗指南》(60页PDF)，使用此技能完成初步结构化仅需2分15秒。医疗信息团队只需复核18页标记内容，节省90%的人工录入时间。

---

### 2. **药品说明书提取**

**场景**: 制药公司或药房需要从药品说明书中提取标准化信息，构建药物知识库。

**使用方式**:

```bash
/extract-medical-doc xxx说明书.pdf
```

**交付价值**:

- **100%准确性要求**: 药物剂量信息自动标记为需人工复核(扫描页)
- 提取不良反应和禁忌症列表
- 识别药物相互作用信息
- 保留表格数据(如儿童用药剂量表)

**真实案例**:
某连锁药房需要为500种药品建立知识库。使用此技能批量处理说明书，自动提取关键字段，药剂师仅需复核剂量等关键信息，大幅提升效率。

---

### 3. **医学文献批量处理**

**场景**: 科研团队需要从大量研究论文中提取特定信息(如某疾病的诊断标准、治疗方案)。

**使用方式**:

```bash
/extract-medical-doc 研究论文_001.pdf
```

**交付价值**:

- 提取文献引用(包括DOI/PMID链接)
- 识别临床试验推荐等级
- 提取诊断标准和评估量表
- 保留图表和表格数据

**真实案例**:
某医学院科研团队进行系统综述，需要分析200篇论文的诊断标准。使用此技能预提取后，研究人员可直接对比结构化数据，文献综述时间缩短50%。

---

### 4. **混合格式文档处理**

**场景**: 医学文档混合包含扫描页和电子页(如旧指南扫描件 + 新附录电子版)。

**使用方式**:

```bash
/extract-medical-doc 混合指南.pdf
```

**交付价值**:

- 自动检测每页类型(电子/扫描)
- 对扫描页使用OCR技术提取文本
- 标记OCR置信度低的页面
- 保留原始图像供人工复核

**真实案例**:
某地区卫健委整理历史医疗文件，文档包含1990年代扫描件和2020年电子版。此技能自动处理不同类型，OCR识别后标记模糊页面，避免关键信息遗漏。

---

### 5. **合规性审查辅助**

**场景**: 医疗机构需要审查治疗方案是否符合最新指南要求。

**使用方式**:

```bash
/extract-medical-doc xx指南_2026.pdf
```

**交付价值**:

- 提取所有推荐等级(Level I/II/III, Grade A/B/C)
- 关联具体治疗方案与证据等级
- 提取禁忌症和注意事项
- 生成可对比的结构化数据

**真实案例**:
医院质控部门每年需审查10+科室治疗方案与国家指南的一致性。使用此技能从指南中提取推荐等级和治疗方案，对比现有方案，快速发现差异。

## 核心组件

### 1. **PDFPageDetector (页面类型检测器)**

**职责**: 自动区分电子页和扫描页

**检测逻辑**:

```python
# 判定标准(按优先级):
1. 文本层存在性: len(text) > 50
2. 字体元数据完整性: has_proper_fonts
3. 文本密度: text_area / page_area > 0.1
4. 图像占比: large_images + low_text_density → scanned
```

**输出**:

- `page_type`: "electronic" | "scanned"
- `confidence`: 0.70 - 0.95
- `has_text_layer`: boolean

**核心价值**: 决定后续提取策略(直接读取 vs OCR)

---

### 2. **CompleteTextExtractor (完整文本提取器)**

**职责**: 提取PDF所有内容并保留布局和结构

**技术栈**:

- **PyMuPDF (fitz)**: 文本提取、图像元数据、页面渲染
- **pdfplumber**: 表格识别(布局感知)
- **pytesseract**: 扫描页OCR
- **pdf2image + Pillow**: 页面图像转换

**处理流程**:

```python
for each page:
    1. 检测页面类型 (PDFPageDetector)
    2. 提取文本:
       - 电子页: fitz_page.get_text()
       - 扫描页: 2倍分辨率OCR
    3. 提取表格: pdfplumber.extract_tables()
    4. 提取图像: get_images() + 元数据
    5. 质量控制: scanned + confidence < 0.90 → needs_review
```

**特殊处理**:

- **OCR优化**: 2倍分辨率渲染提高识别准确率
- **表格保留**: 维持表头和数据行结构
- **图像引用**: 记录位置、尺寸、格式，不嵌入base64(节省空间)

---

### 3. **RuleBasedMedicalExtractor (基于规则的医学提取器)**

**职责**: 使用正则表达式识别医学实体

**识别规则**:

| 实体类型     | 正则表达式                                  | 示例           | 上下文窗口 |
| ------------ | ------------------------------------------- | -------------- | ---------- |
| **ICD编码**  | `[A-Z]\d{2}(\.\d{1,2})?`                    | `E11.9`, `I10` | ±50字符    |
| **药物剂量** | `\d+(\.\d+)?\s*(mg\|mcg\|g\|mL)`            | `10mg BID`     | ±30字符    |
| **推荐等级** | `(Level\|Grade\|Class)\s+([ABC]\|[I]{1,3})` | `Grade A`      | ±100字符   |
| **药物名称** | `[A-Z][a-z]+(mab\|nib\|pril\|olol)`         | `阿托伐他汀`   | -          |

**质量保证**:

```python
# 自动标记复核:
needs_review = (
    page_type == "scanned" OR  # 所有扫描页
    confidence < 0.90 OR        # 低置信度
    entity_type == "medication" # 药物强制复核
)
```

---

### 4. **AI-Powered Analyzer (可选AI增强)**

**职责**: 使用Claude API进行深度语义理解

**触发条件**:

- 用户明确确认(成本透明)
- 环境变量 `ANTHROPIC_API_KEY` 已设置
- `anthropic` Python SDK已安装

**AI增强能力**:

1. **治疗方案提取**: 理解"一线治疗"、"备选方案"等语义
2. **诊断标准识别**: 提取多条件组合的诊断标准
3. **不良反应分类**: 按严重程度和发生率分类
4. **参考文献解析**: 识别DOI、PMID、URL并生成链接

**成本控制**:

```python
# 示例: 60页文档
estimated_tokens = pages * 1000  # 60,000 tokens
estimated_cost = tokens * $0.005  # ~$0.30
print(f"预估成本: ${estimated_cost:.2f}")
confirm = input("启用AI? [y/N]: ")
```

## 质量保证策略

### 1. **分级准确性要求**

| 数据类型     | 准确性要求 | 保障措施                                                 |
| ------------ | ---------- | -------------------------------------------------------- |
| **药物剂量** | 100%       | • 扫描页强制人工复核<br>• 提供原始片段<br>• 保留页面图像 |
| **ICD编码**  | 高准确     | • 严格正则匹配<br>• 提取上下文供验证                     |
| **治疗方案** | 完整性优先 | • 保留完整段落<br>• AI语义理解(可选)                     |
| **其他内容** | 不遗漏     | • 双层输出架构<br>• 完整文本备份                         |

---

### 2. **人工复核触发条件**

```python
needs_review = (
    page_type == "scanned" OR              # 条件1: 扫描页
    confidence < 0.90 OR                   # 条件2: OCR置信度低
    entity_type == "medication" OR         # 条件3: 药物信息
    contains_critical_dosage_keywords      # 条件4: 关键词触发
)
```

**关键词示例**: `units`, `mg/kg`, `titrate`, `loading dose`

## 限制与注意事项

### 当前限制

1. **AI功能可选**: 基础版仅使用规则提取，深度语义理解需启用AI(额外成本)
2. **OCR依赖**: 扫描页质量直接影响识别准确率(建议原始扫描≥300 DPI)
3. **语言支持**: 当前支持中英文医学文档(Tesseract配置 `chi_sim+eng`)
4. **图像不嵌入**: 仅提取元数据和引用，不保存base64图像(节省空间)
5. **批处理未实现**: 当前单次处理单个文件，未提供批量接口

---

### 不适用场景

❌ **手写医嘱**: 手写体OCR识别率低(<60%)，不推荐  
❌ **低质量扫描**: DPI < 150的文档OCR效果差  
❌ **非医学PDF**: 通用文档无法受益于医学实体识别  
❌ **实时处理**: 单文档处理需2-5分钟，不适合秒级响应场景

---

### 安全与合规

⚠️ **隐私保护**:

- 本地处理: 文本提取和规则匹配完全在本地执行
- API调用: 启用AI功能时，文档内容将发送至Anthropic API (符合HIPAA BAA)
- 建议: 敏感患者数据仅使用基础版(无AI)

⚠️ **免责声明**:

- 本工具输出仅供决策辅助，不能替代专业医学判断
- 药物剂量等关键信息必须人工复核
- 用户对数据准确性负最终责任

# 示例: 500mg BID, 10单位 每日一次

RECOMMENDATION = r'\b(?:Level|Grade|Class|等级|级别)\s+([ABC]|[I]{1,3}|1[AB]|2[AB])\b'

# DOI
DOI_PATTERN = r'\b10\.\d{4,}/[^\s]+\b'
# 示例: 10.2337/dc24-S001

# 示例: PMID: 12345678

### B. OCR质量优化技巧

| 场景     | 问题         | 优化方案                               |
| -------- | ------------ | -------------------------------------- |
| 文本模糊 | 扫描DPI低    | 提高渲染倍数至3倍: `fitz.Matrix(3, 3)` |
| 页面倾斜 | 扫描器歪斜   | 启用Tesseract自动旋转: `--psm 1`       |
| 表格识别 | OCR丢失结构  | 预处理图像增强对比度                   |
| 多栏布局 | 文本顺序错乱 | 使用 `--psm 3` 单列模式                |

### C. 成本计算器

```python
def estimate_cost(pages: int, use_ai: bool = False) -> float:
    """估算处理成本"""
    base_cost = 0  # 基础提取免费

    if use_ai:
        # Claude API定价 (2026)
        # Sonnet: $3/MTok输入, $15/MTok输出
        avg_tokens_per_page = 1000
        total_tokens = pages * avg_tokens_per_page
        api_cost = (total_tokens / 1_000_000) * 3  # 仅计算输入
        return api_cost

    return base_cost

# 示例
print(f"60页文档 (无AI): ${estimate_cost(60)}")        # $0
print(f"60页文档 (含AI): ${estimate_cost(60, True)}")  # ~$0.18
```
